# Testing strategy and security matrix

`./mvnw -B -ntp clean verify` (`mvnw.cmd` on Windows) compiles, runs unit tests,
packages, starts real PostgreSQL Testcontainers and an actual embedded HTTP server,
runs integration/security/protocol/concurrency tests via Failsafe, then verifies results.
No mocks replace the authentication, OAuth provider, database or session storage.
No critical test can be skipped through `disabledWithoutDocker`. No Thread.sleep;
application expiry uses MutableClock, concurrency uses a CyclicBarrier and bounded futures.

Unit: password boundaries/Unicode/normalization and RFC 6238 vectors/replay window.
Integration: Flyway empty DB, real constraints, append-only trigger, hash/encrypted
storage, browser cookies and revocation. Security/adversarial: HTTP CSRF, ownership,
permissions, abuse windows, state denial, MFA boundary and replay. Protocol: discovery,
JWKS, actual Authorization Code S256 exchange, ID/access tokens, expiry, revocation,
wrong issuer/audience/signature, invalid verifier/URI, refresh rotation and code replay.
Concurrency: exactly one reset/recovery/code/refresh winner; refresh race revokes family.

Tests capture logs and compare actual generated password, client secret, keystore
password, session cookie, access/refresh/ID token, enrollment seed, recovery/reset
credentials where generated by the harness. Assertions compare booleans rather than
printing secrets. `scripts/scan-artifacts.py` adds pattern-based source/report scan.
Pattern scanning is defense in depth, not a complete credential detection proof.

Failure evidence should contain fixed proof text, never raw request/response bodies,
session IDs, keys or credentials. Surefire/Failsafe XML/text can be preserved after
scanning. CI uploads artifacts only if preceding steps and scanner succeed.

Limits: functional/local concurrency proofs are not a load benchmark, formal proof,
independent pentest, distributed abuse simulation or external key-management audit.
